# Swagger / OpenAPI Guide

The Beacon Check-In API publishes generated Swagger 2.0 documentation and an interactive UI.

## Live documentation

| Resource | Local | Production |
| :-- | :-- | :-- |
| Interactive UI (Scalar) | `http://localhost:8080/api-docs` | `https://beacon-check-in-api.playground.my.id/api-docs` |
| Raw spec (JSON) | `http://localhost:8080/api/openapi.json` | `https://beacon-check-in-api.playground.my.id/api/openapi.json` |
| Health check | `http://localhost:8080/healthz` | `https://beacon-check-in-api.playground.my.id/healthz` |

The interactive page is powered by [`scalar-go`](https://github.com/bdpiprava/scalar-go) and reads the embedded `swagger.json`. It is served by the API itself, so it is available anywhere the API is running.

## Files

| File | Description |
| :-- | :-- |
| [`apps/api/docs/swagger.yaml`](../apps/api/docs/swagger.yaml) | Generated Swagger 2.0 YAML. Generated during builds; gitignored. |
| [`apps/api/docs/swagger.json`](../apps/api/docs/swagger.json) | Generated Swagger 2.0 JSON — served at `/api/openapi.json`. Generated during builds; gitignored. |
| [`apps/api/docs/docs.go`](../apps/api/docs/docs.go) | Go package generated by `swag`, embedded into the API binary. Generated during builds; gitignored. |
| [`docs/swagger.yaml`](./swagger.yaml) | Read-only snapshot for documentation browsing. |

`swag` generates from Go annotations in:

- `apps/api/cmd/main.go` — title, description, version, base path and auth scheme;
- `apps/api/modules/*/handler/*.go` — paths, parameters, request/response models and tags.

## Authentication in the UI

Most endpoints require a Bearer token.

1. Sign in with `POST /api/v1/auth/signin/email` or `/auth/signin/username`.
2. Copy the `access_token` from the response.
3. In the interactive UI, open **Authorize** / the auth panel.
4. Enter:

```text
Bearer <access_token>
```

5. Execute protected requests.

The token is a JWT. It expires according to `ACCESS_TOKEN_EXPIRY` (the POC default is 24 hours). Use `POST /api/v1/auth/refresh` with the refresh token to get a new one.

## Regenerating the spec

Install `swag` if needed:

```bash
go install github.com/swaggo/swag/cmd/swag@v1.16.6
```

From the repository root:

```bash
moon run api:generate-swagger
```

This runs:

```bash
swag init -o apps/api/docs -d cmd,internal,modules --parseDependency
swag fmt --dir apps/api/docs
go mod tidy
```

Restart or rebuild the API so the embedded `swagger.json` / `swagger.yaml` are picked up. The API build (`moon run api:build`) depends on `generate-swagger`, so the Docker image always regenerates and embeds the spec.

To refresh the committed documentation snapshot:

```bash
cp apps/api/docs/swagger.yaml docs/swagger.yaml
```

## Format notes

- The generated document is **Swagger 2.0** (`"swagger": "2.0"`), produced by `swag`.
- `@BasePath /` is used because every annotated path already starts with `/api/v1`.
- Auth is declared as an `apiKey` header named `Authorization`:

```yaml
securityDefinitions:
  BearerAuth:
    type: apiKey
    in: header
    name: Authorization
```

Handlers opt in with `@Security BearerAuth`.

- Public endpoints (sign-in, sign-up, refresh, health) have no security requirement.
- Some advanced auth/session endpoints are documented for completeness but are not used by the web or mobile client.

## Verifying the spec

Check that the spec loads and includes the expected paths:

```bash
curl -s http://localhost:8080/api/openapi.json \
  | jq '.info, .basePath, (.paths | keys | length)'
```

Expected title:

```json
{
  "title": "Beacon Check-In API",
  "version": "1.0"
}
```
